## Overview

This project uses two independent SPI peripherals (SPI1 and SPI2) to communicate with two temperature sensor interface ICs. Both SPI interfaces operate in **full-duplex master mode** with **DMA-enabled transfers** for efficient, non-blocking data acquisition.

### SPI Peripherals Summary

| Peripheral | Connected To | Mode | Clock Speed | CPOL/CPHA | DMA Channels |
|------------|--------------|------|-------------|-----------|--------------|
| **SPI1**   | MAX31865 (PT100) | Full-Duplex Master | ~281 kHz | 0/1 | CH2 (RX), CH3 (TX) |
| **SPI2**   | MAX31855 (K-Type) | Full-Duplex Master | ~140 kHz | 0/0 | CH4 (RX), CH5 (TX) |

## SPI Architecture

### SPI Communication Model

```
STM32F103C8 (SPI Master)
        │
        ├─── SPI1 ───▶ MAX31865 (PT100 RTD Sensor)
        │              - Register-based communication
        │              - Read/Write operations
        │
        └─── SPI2 ───▶ MAX31855 (Thermocouple Sensor)
                       - Read-only device
                       - Continuous streaming
```

### Full-Duplex Operation

Both SPI peripherals operate in full-duplex mode:

```
    STM32                           Sensor (MAX31865/MAX31855)
      │ ─────── MOSI (Data Out) ────────▶ │
      │ ◀────── MISO (Data In) ────────── │
      │ ─────── SCK (Clock) ────────────▶ │
```

- **MOSI (Master Out, Slave In):** STM32 sends commands/addresses
- **MISO (Master In, Slave Out):** STM32 receives sensor data
- **SCK (Serial Clock):** Generated by STM32 to synchronize transfer
- **CS (Chip Select):** Software-controlled GPIO (active low)

## SPI1 Configuration - MAX31865

### Purpose

SPI1 interfaces with the **MAX31865 RTD-to-Digital converter**, which reads a PT100 platinum resistance temperature sensor. The MAX31865 has configurable registers for ADC settings, fault detection, and calibration.

### Hardware Connections

| STM32 Pin | Function | MAX31865 Pin |
|-----------|----------|--------------|
| PA5       | SCK      | SCLK         |
| PA6       | MISO     | SDO          |
| PA7       | MOSI     | SDI          |
| PA4       | CS (GPIO)| CS           |

### SPI1 Parameters

```c
hspi1.Instance = SPI1;
hspi1.Init.Mode = SPI_MODE_MASTER;
hspi1.Init.Direction = SPI_DIRECTION_2LINES;       // Full-duplex
hspi1.Init.DataSize = SPI_DATASIZE_8BIT;           // 8-bit transfers
hspi1.Init.CLKPolarity = SPI_POLARITY_LOW;         // CPOL = 0
hspi1.Init.CLKPhase = SPI_PHASE_2EDGE;             // CPHA = 1
hspi1.Init.NSS = SPI_NSS_SOFT;                     // Software CS control
hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_128;
hspi1.Init.FirstBit = SPI_FIRSTBIT_MSB;
```

**Clock Calculation:**
- APB2 Clock: 36 MHz
- Prescaler: 128
- **SPI1 Clock:** 72 MHz / 128 = **281.25 kHz**

### Timing Diagram - CPOL=0, CPHA=1

```
CS   ‾‾‾\___________________________/‾‾‾
         ↑                       ↑
      Start                    End

SCK  ______/‾\__/‾\__/‾\__/‾\______
            ↑   ↑   ↑   ↑
         Sample edges (rising edge)

MOSI ──<D7><D6><D5><D4>──
           Data changes on falling edge

MISO ──<D7><D6><D5><D4>──
           Data sampled on rising edge
```

**Key Points:**
- Clock idles LOW (CPOL=0)
- Data is sampled on the **second edge** (rising, CPHA=1)
- CS must be LOW before first clock edge

## SPI2 Configuration - MAX31855

### Purpose

SPI2 interfaces with the **MAX31855 Cold-Junction Compensated Thermocouple-to-Digital Converter**, which reads K-type thermocouples. The MAX31855 is a read-only device that streams 32 bits of data when CS is pulled low.

### Hardware Connections

| STM32 Pin | Function | MAX31855 Pin |
|-----------|----------|--------------|
| PB13      | SCK      | SCK          |
| PB14      | MISO     | SO (Serial Out) |
| PB15      | MOSI     | (Not connected) |
| PB12      | CS (GPIO)| CS           |

**Note:** MOSI is configured but not physically connected since MAX31855 is read-only. SPI2 is configured in full-duplex mode to generate clock automatically.

### SPI2 Parameters

```c
hspi2.Instance = SPI2;
hspi2.Init.Mode = SPI_MODE_MASTER;
hspi2.Init.Direction = SPI_DIRECTION_2LINES;       // Full-duplex (for clock)
hspi2.Init.DataSize = SPI_DATASIZE_8BIT;
hspi2.Init.CLKPolarity = SPI_POLARITY_LOW;         // CPOL = 0
hspi2.Init.CLKPhase = SPI_PHASE_1EDGE;             // CPHA = 0
hspi2.Init.NSS = SPI_NSS_SOFT;
hspi2.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_256;
hspi2.Init.FirstBit = SPI_FIRSTBIT_MSB;
```

**Clock Calculation:**
- APB1 Clock: 36 MHz
- Prescaler: 256
- **SPI2 Clock:** 36 MHz / 256 = **140.625 kHz**

### Timing Diagram - CPOL=0, CPHA=0

```
CS   ‾‾‾\___________________________/‾‾‾
         ↑                       ↑
      Start                    End

SCK  ______/‾\__/‾\__/‾\__/‾\______
         ↑   ↑   ↑   ↑
      Sample edges (rising edge)

MISO ──<D31><D30><D29><D28>──
        Data ready on first edge
```

**Key Points:**
- Clock idles LOW (CPOL=0)
- Data is sampled on the **first edge** (rising, CPHA=0)
- MAX31855 outputs data immediately when CS goes LOW

## Logic Explanation

### Initialization Sequence

1. **Clock Enable:** Both SPI peripherals and their GPIO ports are clocked
2. **GPIO Configuration:** 
   - SCK and MOSI pins are configured as alternate function push-pull (output)
   - MISO pins are configured as floating input
   - CS pins are configured as GPIO outputs (software-controlled)
3. **DMA Linking:** Each SPI peripheral is linked to its RX and TX DMA channels using `__HAL_LINKDMA()`
4. **Interrupt Enable:** NVIC interrupts are enabled for both SPI and DMA

### Transfer Process (DMA-Based)

The SPI transfers are non-blocking and managed by DMA:

```c
// Example from sensing.c
void max31865_read(void) {
    if (max31865_busy_flag == 0) {
        max31865_busy_flag = 1;
        // Assert CS (active low)
        HAL_GPIO_WritePin(MAX31865_CS_GPIO_Port, MAX31865_CS_Pin, GPIO_PIN_RESET);
        // Start DMA transfer
        HAL_SPI_TransmitReceive_DMA(&hspi1, tx_buf_31865, rx_buf_31865, 9);
    }
}
```

**Steps:**
1. Assert CS pin (LOW) to select sensor
2. Call `HAL_SPI_TransmitReceive_DMA()` which:
   - Configures TX DMA to send data from `tx_buf` to SPI_DR
   - Configures RX DMA to receive data from SPI_DR to `rx_buf`
   - Starts both DMA transfers simultaneously
3. DMA handles the transfer in background
4. When complete, `HAL_SPI_TxRxCpltCallback()` is called
5. In callback: De-assert CS (HIGH) and process received data

### Why Full-Duplex for MAX31855?

Although MAX31855 is read-only, SPI2 is configured in full-duplex mode (`SPI_DIRECTION_2LINES`) because:
- In receive-only mode, STM32 HAL may not generate clock properly
- Full-duplex mode requires both TX and RX DMA to be active
- Solution: TX DMA sends dummy bytes (0x00) to trigger clock generation
- RX DMA receives actual sensor data

### CPOL/CPHA Selection

**MAX31865 (SPI1): CPOL=0, CPHA=1**
- Matches MAX31865 datasheet specification
- Data is stable on rising edge (sampling edge)

**MAX31855 (SPI2): CPOL=0, CPHA=0**
- Matches MAX31855 datasheet specification
- Data is valid immediately when CS goes LOW
